# Accord website: start here

Four files, in this order:

0. `LANDING_PAGE_SPEC.md`: the complete site specification: brand system, every homepage section with its copy and visual direction, the supporting pages, components, states, motion, accessibility, performance, SEO, analytics, site security, legal notes, content governance, the launch checklist and the implementation order. Build from this.
1. `FINAL_COPY.md`: the publication-ready homepage copy, FAQ, footer, metadata and microcopy (Part A), with implementation notes, the list of improvements and the unresolved factual dependencies (Part B). This is what the site says.
2. `RESEARCH_PAGE.md`: the `/research` page copy, organised by the question each source answers, with what each establishes, what it does not, and the design decision it informs; plus the claim-to-source table and the list of claims removed or qualified (Part B).
3. `ARCHIVE_brief_v1.md`: the earlier, longer brief. Superseded. It describes the old settlement on Base through Chain Signatures, which v7 replaced on 31 Oct with USDC on NEAR paid from each agreement's own account. Kept for the design notes and the full numbered reference list; where it disagrees with the files above, the files above win.

On 31 Oct the copy and the diagrams (`attack`, `gates`, `room`, `states`, `visibility`, `threats`, `atlas`) were updated for NEAR settlement; `../LOOP_PROMPT.md` section 4 applies the same changes to the live site.

Headline: "The private deal room and control plane for agent-to-agent commerce." Product names: Accord, Sealed Table, Agreement controls, Payee, Accord Atlas. The interface says deal room; code, docs and events say agreement. The product spec is `../GOAL.md`; the evidence base is `../REFERENCES.md`.

Rules that still bind, in one line each: sentence case; no em-dashes in our own words; monospace for commands, states and amounts in the application; no trust words; no competitor dismissals, judge references, portraits, seals or logo walls; every sourced number resolves to a source; every product behaviour on the page must be shown by the build or come off the page.
